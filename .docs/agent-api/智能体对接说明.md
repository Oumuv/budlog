# Budlog 智能体对接说明（REST v1）

> 交给其他智能体的是本文和交付包内的专用凭据文件，不要提供项目根 `.env`、家庭密码、数据库凭据或生产服务端的 `.agent.env`。本文不包含任何真实 Token 或育儿记录。只读 REST API 已通过生产 HTTPS 验收。

## 连接参数

- HTTPS 入口：`https://1panel.oumuv.org:25173/api/v1/agent/v1`
- 身份验证：每次请求使用 `Authorization: Bearer <BUDLOG_AGENT_TOKEN>`；明文 Token 从随本文**安全单独传递**的 `.env` 中读取，绝不可写进提示词、URL、源代码、日志或聊天记录。
- 凭据文件的 `BUDLOG_AGENT_CLIENT_ID` 是管理用标签，不必发送到服务器；其他智能体应各自申请独立 Token，服务端可按客户端单独撤销/轮换。
- 只允许 GET，任何写入操作和家庭 API（例如 `/api/v1/feedings`）不属于 Agent 授权范围。
- 生产服务已启用；成功响应 `code=0`、`message=success`、`data` 为实际内容；401 为 Token 无效或缺失，404 可表示服务未开启。遇到失败不要凭空生成日报。

## 推荐请求

- `GET /profile`：宝宝所在时区及出生时间。
- `GET /daily-report?date=YYYY-MM-DD`：按宝宝时区获取完整单日快照。建议定时任务请求**昨天**，避免把未录完的今天与全天对比。
- `GET /feedings/trends?days=7&endDate=YYYY-MM-DD`：昨日为结束日的七天趋势及前七天对比；30 天趋势用 `days=30`。
- `GET /feedings?from=YYYY-MM-DD&to=YYYY-MM-DD&page=0&size=50`：按开始时间降序的分页原始喂养记录（最多每页 100 条）。其他接口及完整字段见 [OpenAPI](openapi.yaml)。

查询中的 `from`、`to` 含两端自然日，均使用宝宝时区（现为 `Asia/Shanghai`），默认最多 90 天。`/feedings/trends` 的 `endDate` 不提供时默认昨天。

## 解释限制

瓶喂可测量奶量只计入已记录的母乳瓶喂及配方奶瓶喂。亲喂时长不能换算为毫升；`totalIntakeKnown=false` 或 `measuredBottleIntakeKnown=false` 表示不能把已记录量当作全天总量。`milkStorage.addedMl` 是新增存奶而不是摄入量或现有库存；尿便 BOTH 同时计入尿与便事件；旧体重须连同 `measuredAt` 解读。空记录不代表没有喂养或尿便，不做医疗诊断。请求失败、无记录或数据质量不确定时，应明确标注，不得编造健康判断。

## 调用方接入边界

仅凭这份 REST 文档及 Token，适合可自行设置 HTTPS Bearer 头的服务端智能体（如 Hermes/Codex）调用。**ChatGPT 的自定义 MCP 应用不是普通 REST 客户端**：仍需独立托管远程 MCP 网关及其 OAuth/可刷新授权，不能假定把本 `.env` 上传给 ChatGPT Scheduled Tasks 就能无人值守调用。不要把长期密钥直接交给不受控插件、共享 prompt 或聊天会话；若需调用，请先通过受信任的服务器端连接器管理凭据。ChatGPT 云端定时任务和推送尚未创建或验证。

## 凭据保管

交付包中的 `.env` **只含** `BUDLOG_AGENT_TOKEN`、`BUDLOG_AGENT_CLIENT_ID`、`BUDLOG_AGENT_TOKEN_SHA256` 三项，不含家庭密码/数据库信息。将它保存在仅目标智能体可读取的安全位置（权限 0600），不得提交 Git、上传公开网盘或通过明文 IM 传播；若发生泄露，请撤销对应客户端并轮换。`BUDLOG_AGENT_TOKEN_SHA256` 是供运维配置匹配时核对的摘要，不应发送在 HTTP 请求中。
